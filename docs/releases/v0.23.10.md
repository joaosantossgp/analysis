# CVMAnalytics v0.23.10 — Current-year ITR refresh fix

`v0.23.10` fixes refresh planning so the **current calendar year is
eligible for ingestion**. Previously the planner capped refresh at
`current_year - 1`, so during 2026 the year 2026 was dropped as a
"future" year before any download — quarterly ITR such as **1T26** was
never planned, downloaded, processed, or surfaced for companies like
Petrobras (CVM 9512) and Equatorial (CVM 21369), even though the data
existed at CVM.

## Fixed

- **Current year no longer dropped as "future".**
  `HeadlessRefreshService.build_company_year_plan()` now caps the
  planning scope at the current calendar year instead of the last closed
  year. Strictly future years (`current_year + 1` and beyond) remain
  blocked and counted in `dropped_future_years`.
- **Current-year quarterly data is no longer mistaken for annual
  completeness.** `_load_complete_company_years()` only marks a year
  complete when `REPORT_YEAR <= last_closed_year` and the annual (DFP)
  package is present. Current-year ITR can no longer short-circuit a
  company to `already_current`, so new quarters stay refreshable.
- **On-demand and batch refresh default through the current year.**
  `resolve_refresh_year_range()` and `CVMReadService._resolve_refresh_range()`
  now default `end_year` to the current year (an explicit `end_year`
  still overrides). A company-page "Atualizar" with no explicit window
  now reaches the current year's ITR.

## Internal

- New shared helper `current_reporting_year_cap()` in
  [src/financials/utils.py](../../src/financials/utils.py) is the single source of truth for
  the maximum eligible reporting year. `MAX_AUTO_REPORTING_YEAR_LAG` now
  scopes only annual (DFP) completeness, not the future-year cap.
