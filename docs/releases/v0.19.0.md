# CVMAnalytics v0.19.0 — Analyst-Ready Excel Model (Refined)

CVMAnalytics `v0.19.0` is a substantial refinement of the company Excel
export. The previous workbook (`v0.18.2` / `v0.18.3`) consolidated all
statements into one sheet but still felt like a formatted CVM raw data
dump — wide, granular, and prone to `#NUM!` errors. This release
redesigns the workbook around a compact, analyst-curated `Model` sheet
with formula-driven KPIs, formula-driven checks, an explicit period-
end-date row, and demoted raw audit sheets.

## Summary

- **New `Model` sheet** (renamed from `Financial Statement Model`) is
  the single visible analyst surface. Compact (~25 columns × ~110
  rows for Petrobras, vs. ~76 columns × ~700 rows previously).
- **`README` sheet** is the only other visible sheet. Sheet map,
  conventions, period policy, audit instructions.
- **`raw_DRE` / `raw_BPA` / `raw_BPP` / `raw_DFC` /
  `raw_KPIs` / `metadata`** sheets ship hidden by default. Full CVM
  tree and full period history preserved for audit; right-click any
  tab → Unhide…
- **Period window** is now controlled by `(annuals, quarters_per_year)`
  with default `(5, 4)`. Selects the last 5 annual fiscal years plus
  the four quarters of each of those years, interleaved
  chronologically: `1Q21, 2Q21, 3Q21, 4Q21, 2021, 1Q22, ..., 4Q25,
  2025`. Falls back gracefully when fewer than 5 annuals are
  available.
- **Period header is now 3 rows**: `Period` / `Period end date` /
  `Period type`. End dates are real Excel dates formatted as
  `dd/mm/yy` (`1Q25 → 31/03/25`, `2024 → 31/12/24`).
- **Formula-driven Model.** Every imported line is a cross-sheet
  formula like `=IFERROR('raw_DRE'!E2/1000,"-")` (linking and scaling
  R$ mil → R$ mm in a single cell). Computed lines (EBITDA, FCF) are
  formulas referencing other Model rows.
- **Formula-driven KPIs.** All ratios are
  `=IFERROR(numerator/denominator,"-")` — no more pre-computed
  `#NUM!` slip-through. Includes Revenue Growth, Gross/EBITDA/EBIT/Net
  Margin, ROE, ROA, Net Debt / EBITDA, Current Ratio, CFO/Revenue,
  FCF/Revenue, Capex/Revenue.
- **Formula-driven Checks.** Balance Sheet tie computed per period,
  status via `SUMPRODUCT` over the diffs row. Critical Line
  Availability flags any missing analyst-spine line.
- **Post-write validator.** Every workbook is re-opened with openpyxl
  immediately after `xlsxwriter.close()` and walks every cell — any
  `#NUM!` / `#REF!` / `#VALUE!` / `#DIV/0!` / `#NAME?` / `#N/A` slip-
  through aborts the export with `ExcelExportError`. The published
  workbook is guaranteed error-cell free.
- **Inf-safe numeric writes.** `_is_safe_number()` rejects infinity
  and NaN before any `write_number()` call. Solves the
  `pd.isna(v)` → catches NaN but not Inf gap that produced the
  `#NUM!` cells in the legacy `KPIs` sheet.
- **Improved conventions legend.** 7 swatches now: Input / Output /
  **Linked** (new — green for cross-sheet refs) / Calculation / Check
  / Note / Warning, plus a "(red) negatives shown as (123)" example.
- **Negative-in-parens-and-red number format.**
  `#,##0;[Red](#,##0);-` instead of the previous all-black layout.

## Breaking changes (sheet rename)

- `Financial Statement Model` → `Model`
- `DRE` / `BPA` / `BPP` / `DFC` (legacy raw sheets) →
  `raw_DRE` / `raw_BPA` / `raw_BPP` / `raw_DFC`
- `KPIs` → `raw_KPIs`
- `METADADOS` → `metadata`
- `CAPA` and `GERAL` sheets are removed; their information folds into
  the new `Model` company-info block and the `README` sheet.

Any external tooling that opened sheets by name needs to be updated.
Default bridge / desktop UI / output filename are **unchanged**.

## Architecture Notes

- No Node/Next runtime reintroduced.
- No persistent user data paths changed.
- No database schema changes.
- No new Python or npm dependencies (`openpyxl` was already used by
  tests and is now also used by the post-write validator).
- Bridge surface unchanged (`export_company_excel`, `get_output_dir`).
- Filename convention unchanged.

## Known Limitations

- No forecast periods.
- No LTM column on the Model sheet.
- No per-share rows, share counts, market prices, EV-based KPIs.
- No sector-specific KPIs (utilities-specific RAB metrics, banking-
  specific ratios, etc.).
- Period-end dates are derived inside the exporter from the period
  label (no `DT_FIM_EXERC` plumbed through the read service yet).
- Period window is a power-user knob on `ExcelExporter` — not yet
  exposed via the desktop UI.
