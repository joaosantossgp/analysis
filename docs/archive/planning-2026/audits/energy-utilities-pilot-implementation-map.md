## Existing capabilities

1. The first four families are not missing data models. ONS load, generation/mix, EAR, ENA, and CMO are already cataloged, ingested, persisted, read offline, bridged, typed, and reachable in the active Vite app.
2. The inspected local database contains usable 2025–2026 ONS history for all four ready families. CMO remains available despite CCEE PLD failure, satisfying the contract's required separation of those signals.
3. Refresh is explicit and observable. It defaults to the current and previous year, preserves successful ONS rows when CCEE fails, records partial/error details, and does not make network calls on normal reads (`src/energy_kpi/sin_refresh.py:66-177`).
4. The Power System view already handles loading, browser-only, dashboard error, empty cache, stale cache, backend refresh, partial refresh error, and cached-data-during-refresh states (`apps/desktop-web/src/components/indicators/SINKpiPanel.tsx:354-450,488-525,643-669`). Missing audit-table values render as `—` (`apps/desktop-web/src/components/indicators/SINKpiPanel.tsx:875-884`), although the generation-mix exception is recorded below.
5. Source provenance is visible in the specialist Power System view: provider, dataset, frequency, local record count, snapshot time, last status, and source error (`apps/desktop-web/src/components/indicators/SINKpiPanel.tsx:819-855`).
6. Capacity-related plant/parcel schemas, source status, manual-import fallbacks, bounded marts, bridge methods, and a Generation specialist route already exist. These are useful investigation inputs but do not satisfy the blocked aggregate capability.

## Real gaps

1. **Health is refresh-global, not family/source-specific.** Every SIN source card inherits the latest overall refresh status, so successful ONS cards show `partial` when only PLD failed. The dashboard's seven-day stale flag uses the maximum timestamp across all SIN rows, allowing current CMO to mask older/missing PLD or hydrology. The source query computes `latest_reference` but the DTO does not expose it (`src/energy_kpi/read.py:1158-1199`; `src/platform/contracts.py:956-977`).
2. **PLD risk is not consistent across surfaces.** The specialist source panel shows the persisted PLD error, but Indicator Library status uses the bridge's current in-memory `refresh_error`, not each `source_status.last_error`; after restart PLD can appear only “missing” while the actual 403 remains in the refresh log (`apps/desktop-web/src/lib/indicators/registry.ts:299-337`).
3. **CMO historical previews can be materially wrong.** The read service orders ascending before applying `LIMIT 50000`. Read-only reproduction against the active database showed 105,984 eligible CMO rows, but the Library request returned only through 2025-09-19; the one-year detail returned only through 2026-03-31 although the database reaches 2026-07-09. Load's one-year window stayed below the limit and included its latest row. This is a bounded-series ordering defect, not missing CMO data.
4. **Approved analytical roles are not visible.** The active screens organize by KPI categories such as Load, Generation, Reservoirs, Hydrology, and Prices, but do not group the four approved families or state that load/supply/hydro are explanatory while CMO/PLD are confirmatory only. No causal claim is currently made, but the anti-circularity caveat is absent.
5. **Power System history is discoverable indirectly.** `SINKpiPanel` implements a trend mode, but the active route always passes `viewMode="matrix"`. Individual history remains available through Indicator Library detail charts, so history is partially connected rather than missing.
6. **Some failure and missing states are misleading.** Catalog/health query failures are not rendered by Power System; its unreachable trend branch collapses a series error into “Nothing to plot.” The generation-mix graphic maps missing values to `0`, so missing and measured zero are not distinguishable (`apps/desktop-web/src/components/indicators/SINKpiPanel.tsx:589-615,697-731`).
7. **The SIN detail change label is incorrect.** The detail panel labels the change “YoY” but `computeChange` compares only the last two finite daily points (`apps/desktop-web/src/components/indicators/explorer/IndicatorDetailPanel.tsx:175-193,450-465`). It cannot be used as annual demand pressure or structural trend evidence.
8. **Actual local horizon is bounded.** The default refresh gives current and previous years and the active local store starts on 2025-01-01. That supports recent historical/current diagnosis, but not a long-cycle or forward-looking adequacy claim.
9. **Documentation drift exists.** `docs/reference/energy-utilities-sin-kpis.md:7-8,52` still names `Macroeconomic -> SIN Subsystems` and points generally to `desktop/bridge.py`; the active location is Energy -> Power System and the domain methods live in `desktop/bridge_api/energy.py`. The older readiness audit asks which of PLD/CMO should be primary and labels capacity merely partial (`docs/energy-utilities-source-driver-readiness-audit.md:38-44`), both superseded by the approved decision.
10. **Packaged execution was not reproduced.** Build/runtime wiring is verified, but no packaged executable existed in the checkout and no clean-machine desktop run was performed.

## Blocked capabilities

- Capacity and firm-supply headroom remains blocked exactly as approved. Existing plant and parcel fields are evidence at their source grain only.
- No headroom formula, aggregate, score, status, bridge method, UI row, or Indicator Library metric is authorized.
- Installed capacity must not be treated as firm supply. Physical guarantee must not be treated as operational availability. `MW` and `MWmed` must not be added or directly compared.
- The active local database currently contains no plant/parcel rows or marts, so even investigation-level asset evidence is unavailable until an explicit, separately authorized source import occurs.
- A separate Decision task must establish an approved aggregate contract before any implementation task is proposed for this capability. This report intentionally does not propose that contract's formula.
- CCEE PLD is source-blocked in the inspected environment, but that does not block ONS CMO or invalidate the entire confirmatory family.

## Risks and unknowns

- CCEE PLD access behavior may differ by network/runtime, but two persisted local attempts failed with HTTP 403 and the code/catalog explicitly treat direct access as risky. Reliability is therefore partial, not universally impossible.
- The inspected local database proves João's current Documents data root only. A different user or isolated data root may have different snapshots, PLD rows, or plant imports.
- The non-active repository database at `data/db/energy_kpis.db` differs from the Documents store: a read-only check found 25,250 ANEEL SIGA plants dated 2026-06-01 but no CCEE plant/parcel rows. Default desktop dev and packaged modes do not use that repository database, so it is investigation evidence only and does not change the active-runtime readiness classification.
- The seven-day global SIN stale threshold is implemented but not family-specific. An approved cadence policy per dataset is not currently encoded.
- Source inspection does not prove packaged WebView2, PyInstaller, filesystem permission, or clean-machine behavior.
- The browser mock is intentionally synthetic and must not be used as evidence of source availability, historical grain, freshness, or packaged behavior.
- Historical/current diagnosis is supported only over locally refreshed history. No forward-looking adequacy, EPE outlook, commissioning pipeline, retirement, or scenario conclusion is proven.
